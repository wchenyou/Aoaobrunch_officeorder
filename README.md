# 嗷嗷早午餐｜辦公室團購點餐系統

讓辦公室同事自己上網點餐、系統自動彙整、主揪一鍵送單通知店家的小系統。全部用免費服務，不需要租主機。

- **前端**（點餐頁面）→ GitHub Pages
- **後端**（資料與通知）→ Google Apps Script + Google 試算表
- **通知方式** → 主揪按下「送單」時，寄一封彙整好的訂單信給店家

---

## 怎麼運作

```
同事的手機                GitHub Pages              Apps Script              Google 試算表
   │                    (order.html)              (JSON API)
   │  ── 選餐、送出 ──▶      │  ── fetch() ──▶         │  ── 寫入一列 ──▶        │
   │                         │                        │
主揪的手機                (admin.html)                │  ── 送單時寄信 ──▶  店家信箱
   │  ── 按下送單 ──▶       │  ── fetch() ──▶         │
```

三個頁面：

| 頁面 | 誰用 | 做什麼 |
|---|---|---|
| `index.html` | 主揪 | 填一次訂購資訊，建立揪團，拿到兩個連結 |
| `order.html?session=xxx` | 全辦公室 | 看菜單、選規格、送出訂單，截止前可自行修改或取消 |
| `admin.html?session=xxx&admin=yyy` | 主揪 | 看即時統計與所有訂單、按下送單 |

## 安裝步驟

### 一、後端（Google Apps Script）

1. 建立一份新的 Google 試算表，**檔案 → 設定 → 地區改成「台灣」**。
2. **擴充功能 → Apps Script**，把 `apps-script/Code.gs` 的內容整個貼進去，存檔。
3. 在編輯器上方選 `setupSheet` 函式，按 **執行**。第一次會跳授權，照著同意即可。
   跑完回試算表，會看到自動建好的四個工作表：**菜單／訂單／揪團／設定**，菜單已經填好嗷嗷早午餐的品項與價格。
4. 打開「設定」工作表：
   - **店家收單Email** → 改成真正要收訂單的信箱
   - **颱風假政策文字** → 改成實際內容（會顯示在點餐頁面上）
   - **前端網址** → 建議填上 GitHub Pages 的網址（例如 `https://帳號.github.io/repo/`）。這是寄給主揪的管理連結會用的網域；留空的話會用建團當下前端傳過來的網址。
5. **部署 → 新增部署作業 → 類型選「網頁應用程式」**
   - 執行身分：**我**
   - 具有存取權的使用者：**任何人**
6. 複製部署後的網址（結尾是 `/exec`）。

### 二、前端（GitHub Pages）

1. 把這個 repo 推上 GitHub。
2. 編輯 `docs/config.js`，把剛剛那串 `/exec` 網址填進去：
   ```js
   const API_URL = "https://script.google.com/macros/s/AKfycb.../exec";
   ```
3. GitHub repo → **Settings → Pages** → Source 選 **Deploy from a branch**，
   branch 選 `main`、資料夾選 **`/docs`** → Save。
4. 等一兩分鐘，網址會是 `https://<你的帳號>.github.io/<repo 名稱>/`。
   打開它就是「發起揪團」頁面。

### 三、試跑一次

用手機打開 Pages 網址 → 建立一個明天的團 → 用點餐連結點兩筆 → 回管理頁按送單 → 確認信箱有收到訂單信、試算表有資料。

## 日常維護

**改菜單、改價格、上下架**：直接改試算表的「菜單」工作表，不用碰程式碼。

- `供應中` 取消勾選 → 該品項就不會出現在點餐頁
- `規格1／規格2` 是客製化選項（醬料、冰量、甜度…），選項之間用**半形逗號**分隔
- `單價L` 留空 → 該品項只有一種價格（例如餐點、咖啡）

**改店家規定文字**：改「設定」工作表。

**改程式碼之後**：Apps Script 那邊要 **部署 → 管理部署作業 → 編輯 → 版本選「新版本」**，網址才會更新到最新版；前端則是 push 上 GitHub 就會自動更新。

## 主揪怎麼找回自己的管理頁

主揪常常把點餐連結貼到群組後就把分頁關掉，等要收團才回來，所以做了兩層保險：

**一、這台裝置會記得。** 建團成功（或用管理連結打開過管理頁）之後，會在瀏覽器的 localStorage 留一筆紀錄。之後重新打開首頁，最上面就會出現「你開過的團」，顯示公司名稱、狀態、剩多久截止，按一下直接回到管理頁。紀錄保留 14 天，也可以手動移除。

**二、建團時會寄一封信給主揪。** 信裡有點餐連結和管理連結，所以換手機、清快取、電腦重灌都還找得回來。因為這層的關係，**主揪 Email 是必填欄位**。

刻意沒做的是「用公司名稱查回管理連結」：公司名稱在辦公室裡不是秘密，如果輸入公司名稱就能拿到管理權限，任何同事都可以提前把團送出去。如果之後真的需要，建議做成「輸入公司名稱 → 把連結重新寄到當初留的信箱」，而不是直接顯示在畫面上。

## 響應式（RWD）

三個頁面都是手機優先設計，隨螢幕寬度換版型：

| 寬度 | 版型 |
|---|---|
| ~599px（手機） | 單欄。點餐頁底部有浮動的購物車列，隨時看得到小計與送出鈕 |
| 600–899px（平板） | 一樣單欄但留白與字級放大，觸控目標更好按 |
| 900px 以上（桌機） | 雙欄。點餐頁左邊菜單、右邊固定跟隨的購物車與送出區；管理頁左邊訂單、右邊訂購資訊與送單鈕。底部浮動列在桌機自動隱藏，改用側欄的按鈕 |

建立揪團的表單在桌機也會變成雙欄，不會只剩中間一條。所有版型都測過沒有橫向捲動。

## 幾個設計上的決定

**通知只在送單時寄一封。** 不是每筆訂單都發信，避免洗版店家信箱。送單那一刻店家會收到一封完整的信：每個人點了什麼、品項加總（方便備餐）、總金額，以及公司／統編／聯絡窗口／送達時間等資訊。

**收單截止時間會被系統擋。** 店家規定最晚前一日 15:00 下單，所以建立揪團時，如果截止時間設得比「預訂日期前一天 15:00」還晚，系統會直接擋下來。截止之後，同事就不能再點餐或修改。

**價格一律由後端算。** 前端傳過來的價格不會被信任，後端會重新從「菜單」工作表查一次單價再計算小計。

**POST 用 `text/plain` 而不是 `application/json`。** 這是為了避開瀏覽器的 CORS 預檢（Apps Script 不會正確回應 OPTIONS 請求）。後端照樣把內容當 JSON 解析，細節寫在 `docs/api.js` 的註解裡。

## 已知限制

- **修改訂單的連結不是帳密等級的保護**：連結裡的 8 碼訂單編號是隨機的，但拿到連結的人就能改那筆訂單。辦公室訂午餐這種場景還好，不適合放機敏資料。
- **管理頁不是即時推播**：每 20 秒自動更新一次（Apps Script 不支援 WebSocket）。
- **飲料的冰量／甜度選項是依菜單圖推斷的**：實際規則如果不同，改「菜單」工作表即可。
- **時間一律以台北時間（UTC+8）計算**。
- **Apps Script 免費額度**：一般 Google 帳號每天約 100 封信、以及一定的執行時間額度。現在每建一個團會寄一封信給主揪、送單時再寄一封，辦公室規模還是遠遠用不完。
- **localStorage 只存在該台裝置**：無痕模式、清除瀏覽資料、換裝置都會消失，這時要靠建團時寄出的那封信。

## 檔案結構

```
apps-script/
  Code.gs          後端：JSON API、試算表讀寫、送單信、初始化
docs/              ← GitHub Pages 就是指這個資料夾
  index.html       發起揪團
  order.html       點餐 / 改單 / 取消
  admin.html       主揪管理與送單
  style.css        設計系統（色彩、元件、深色模式）
  api.js           呼叫後端的共用函式
  ui.js            共用元件（頁首、頁尾、複製按鈕、倒數計時）
  config.js        ★ 要填入你的 Apps Script 網址
```
